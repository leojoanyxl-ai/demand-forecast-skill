# 后续维护与交接

适用对象：继续修改本项目的组员或开发者。当前计算案例信息截止2026-11-03，预测2027—2028。项目说明更新不代表重新估计了经济参数。

## 接手先做三件事

1. 保留下载版本和原输出，阅读[组员分享要点](组员分享要点.md)、[Skill入口](../demand-forecast/SKILL.md)与[实际验证记录](验证记录.md)。不要把“程序完成”读成“真实业务通过”。
2. 保持输入不变跑通新能源汽车和ABS，确认自己环境中的结果与交付结果一致，再开始修改。
3. 在GitHub新建修改分支，一次只处理一个明确问题，记录改了什么、证据是什么、影响哪条结果。每次运行使用一个尚不存在的新输出目录。

## 要改什么，去哪里改

以下路径均相对仓库根目录。

|修改目标|主要入口|注意事项|
|---|---|---|
|Skill任务与判断规则|`demand-forecast/SKILL.md`、`references/`|保持两个行业的需求定义、证据与缺数降级规则；不要写成固定复制某一次结论|
|新能源月度销量／出口|`demand-forecast/assets/nev-monthly.csv`|同时核对汽车销量、汽车出口、新能源销量、新能源出口；保留来源、发布时间与推导性质|
|新能源年度与近期证据|`demand-forecast/assets/nev-evidence.json`|2026全年桥接是估计；不能把未来全年作为已知实际值|
|新能源原始弹性、范围和网格|`demand-forecast/assets/economic-parameters.json`|修改来源、中央值、范围和网格要一致；运行时由转换程序生成模型系数|
|新能源未来路径或本次参数覆盖|`demand-forecast/assets/nev-settings.json`|`scenario_overrides`改路径，`economic_parameters`覆盖原始弹性目标；不用旧的直接模型系数覆盖|
|新能源真实企业输入|`demand-forecast/assets/company-input.csv`|教学文件带example，不能混成实际数据；份额、库存、产能与单位要同口径|
|ABS月度输入和来源|`demand-forecast/assets/abs-monthly.csv`、`abs-source.json`|规模单位亿元、数量单位只；数量为新增备案专项计划数，辅助存量及成交额不与新增量相加|
|ABS未来压力路径|`demand-forecast/assets/abs-settings.json`|项目／计划数量增长、单均规模增长分别输入并逐年累乘；没有利差识别时不声称它们来自利率弹性|
|ABS企业参数|`demand-forecast/assets/abs-company.json`|两类份额、费率、每只计划工时及可用工时分开；缺数留null，教学值不冒充事实|
|新能源计算|`demand-forecast/scripts/run_full.py`、`economic_scenarios.py`、`parameter_mapping.py`、`monthly_demand.py`、`planning_bridge.py`|方法变化需重跑适当历史验证和行为检查，不能只改报告解释|
|ABS计算与选模|`demand-forecast/scripts/abs_forecast.py`|保持训练数据边界、同起点比较、规模／数量分开、总量／月度误差并列|
|统一运行入口|`demand-forecast/scripts/run_skill.py`及启动文件|分析代码用标准库；可选Excel导入另需openpyxl，不应让正常分析因此不能启动|
|自动生成的汇报说明、讲稿和首页|`tools/build_delivery.py`中的生成内容|这些输出会在打包时重新生成，直接改输出可能被覆盖|
|人工维护的分享与交接说明|`docs/组员分享要点.md`、`docs/维护交接.md`|先改Markdown，再打包生成HTML；摘要数字是当前快照，输入改后要同步核对|

`assets`简称均指Skill内的assets目录，不能误改运行结果中的输入快照。参数表、情景设置、结果CSV承担不同职责，结果不能反过来伪装成历史输入。

## 按修改类型选择验证

|修改类型|需要做的核查|
|---|---|
|仅说明文字、排版、交接|核对数字、链接、生成后的页面与压缩包内容，不把它写成模型精度提升|
|只改未来情景或企业假设|重跑对应行业和条件核算，确认成立条件、单位及缺数状态；预测变化不应被说成新增实证证据|
|补历史数据、改口径或参数识别|检查连续性、来源、发布时间、版本与实际／估计性质；重新做时间顺序验证和方法比较，解释与旧版差异|
|改算法、公式、选模或行业适配器|补有意义的行为检查，并验证训练边界、加总恒等式、压力方向、相同起点与相近提前期；保留朴素比较基准|
|添加新行业|先定义需求主体、目标、单位、供需边界，再补本行业机制、数据、适配器、经营映射和验证；不能只替换表头或行业名称|

## 更新到新的信息截止日尤其要处理

新能源当前 `run_full.py` 明确限制2026-11-03及2025为最近完整历史年。更新时先核验新发布数据、税费规则和2028等后续政策，再调整相应校验与配置；不要为让程序通过而直接删掉日期检查。

ABS来源记录及可选工作簿导入器含本案例2026年9月简报的日期与核验状态；更新数据不能沿用成已核验的新来源。当前第4—15、第16—27月回测窗口对应最后实际月2026年9月；末期变动后，应重新计算与目标日历年对应的提前期，不能仍称旧窗口匹配新计划。

ABS当前适配器要求规模和计划数均为正，遇到零新增月份会拒绝运行。扩展到稀疏备案细分前，需要单独设计零值、单均规模和降级策略，不能把缺数填成零或为过校验填成小正数。

两模块的代表车型、税基、持有期、单项工时等示例不是行业实测平均值。取得新的实际参数时记录来源和性质，并重新检查转换、覆盖与适用范围。

## 可复用的运行与交付命令

在仓库根目录执行，路径使用新的目录名：

```sh
python demand-forecast/scripts/run_skill.py --industry nev --output-dir output/nev-my-change
python demand-forecast/scripts/run_skill.py --industry abs --output-dir output/abs-my-change
python -m unittest discover -s demand-forecast/scripts -p "test_*.py"
python tools/check_delivery.py
python tools/build_delivery.py
```

`--demo`用于明确标记的企业教学核算，`--open`用于自动打开报告。这里的命令是接手示例；数据、算法没有变化时不必反复运行全部模型来证明文字修改正确。

打包生成 `dist/demand-forecast-skill-final.zip`（完整课堂交付）与 `dist/demand-forecast-skill-only.zip`（纯Skill）。`dist`不进入Git版本跟踪，发布到GitHub时作为Release附件上传。不能只提交代码而漏掉其必需数据、配置或引用文件。

当前未要求把某人的私人邮箱或令牌写入项目。仓库为私有，现有运行数据已保留；需他人协作时由仓库拥有者授予对应访问权限，或直接分享完整包，不改变运行逻辑。

## 修改交接记录模板

- 修改人、分支／提交、项目版本、信息截止日。
- 原问题与目标决策；改动文件和证据来源。
- 数据是原始观测、差分、外部研究、规划假设还是企业教学值。
- 旧版／新版预测、分支误差及业务行动的变化；变化原因是否能解释。
- 实际做了哪些验证、尚未验证什么；是否有人用新案例独立跑通。
- 留给下一位的缺口、建议顺序和负责人，不把未完成项写成已通过。

建议下一步优先：补同口径更长历史与发布版本 → 补企业实际订单／管线和约束 → 补价格、利差、资产池、海外结构 → 检查新方法的增益 → 做真实前瞻跟踪与组员独立试用。
