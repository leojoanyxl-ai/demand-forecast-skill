给组员的项目要点

信息口径：2026年11月3日可得信息，制定2027年预案并评估2028年风险。本文是当前课堂案例摘要；后续修改数据或假设后，需用新报告同步这些数字。

1. 我们交付的是什么

一个“行业需求预测与经营计划助手”Skill，内置新能源汽车和ABS两个可运行模块，包含规则、数据、参数、计算程序、历史验证、报告与讲稿。业务负责人和战略部门使用它制定有条件的经营预案。

普通模式没有企业内部数据也能完成行业分析，企业部分给公式和待补清单；教学模式用标注的假设演示完整核算。计算可以离线完成，不需要付费接口或原电脑上的Excel路径。

2. 它怎样运作和计算

共同流程：明确决策 → 核对数据与口径 → 分析经济机制 → 比较基线和回测 → 构建三情景 → 条件经营核算 → 输出“建议＋理由＋适用条件＋风险”。

模块核心计算怎样影响经营安排
新能源汽车国内新能源销量＝国内总车市×新能源份额；总销量＝国内＋出口。国内分析收入、相对购置及使用成本、补能、税费；出口另看海外需求、汇率、相对价格、退税传递与准入结合企业份额、库存、供给与有效产能，核算销售机会、生产需要和产能缺口；缺真实输入时不给虚构预算
ABS新增备案规模＝新增备案专项计划数×单均计划规模。先比较统计基线，再对数量与单均规模施加明确的规划压力结合企业规模份额、数量份额、收费与每只计划工时，核算机会量、费用敏感性和工时缺口

ABS“计划数”不是债券分层数量或企业独立项目数。备案是已实现融资活动，不是潜在需求。汽车厂家销量也不是终端零售。两行业不能共用同一套政策、弹性和产能公式。

ABS本次实际选中近12月均值法，2027、2028基准同为15794.81亿元、1657只计划，来自均值延续与零附加增长压力，不是实证证明未来两年一定零增长。

3. 从最初版改进了什么

阶段主要变化
最初小组成果已有经济机制、数据规则、11年总体历史、预测CSV和快照；实际量化主要依赖新能源总体份额趋势与情景假设
可运行与扩大验证增加运行入口、使用说明和更多历史验证起点，发现短期成绩不能代表长期稳定
明确经营任务区分工具使用者与需求主体，增加任务卡、数据证据等级和企业缺数时的条件核算
拆开国内和出口使用同口径加总，分别解释驱动、分别看误差，识别相互抵消
补前瞻经济机制把收入、相对成本、补能、税费、海外因素接入有依据或明确假设的情景；没量化的因素单列
统一数据和参数增加57个月月度需求入口、五年年度参照、销量弹性到模型系数的转换，统一参数中央值、范围、网格和报告
落地跨行业与交接增加ABS81个月数据、数量×规模分解、训练内选模和相近提前期验证，形成统一Skill、GitHub项目与压缩包

这些阶段对应实际材料和修改，不等于事后补出的早期Git提交，也不能虚构谁完成了多少贡献。

原版11年是总体口径，当前五年是同口径国内／出口分支参照，不能说年度样本一路增多。57个月月度序列目前主要用于核对、简单基线回测和年／月对账，尚未全部训练进前瞻宏观动态回归。

4. 用了哪些理论，解决什么问题

理论实际用途
需求、需求量与预算约束区分价格引起的购买量变化、收入等条件变化，以及交易能否实现
收入与价格弹性描述比例响应；购价弹性要经购车总成本导数转换，销量弹性不能直接当份额logit系数
替代和互补效应比较新能源与燃油车的相对全成本、补能与新能源互补；比较ABS与贷款／债券融资替代
宏观传导与信用约束收入影响耐用品购买；经济活动同时影响ABS融资需要、合格资产池、风险及投资者承接，净作用不能机械预设
跨期选择和政策时点购车抢购、项目提前或延后可能只是时间转移，不全是新增长期需求
存量流量与边际决策生产、销量、库存、产能分别处理；ABS新增备案、期末存续和二级成交不能混加；条件不足时不声称最优投资

可用一个例子说明理论确实影响了计算：补能销量弹性满足 η=(1−p)γ，其中p是新能源份额，γ才是logit系数。原先直接填0.3，在份额约0.68处只隐含约0.096的销量弹性。现在按锚点转换，并报告未来隐含弹性。

上述0.68是旧版本的示例口径；当前2027基准份额约0.661，固定转换后系数γ约0.724时，当期隐含补能销量弹性约0.246。它是模型内局部导数，不是本地实证估计。未来收入、成本和补能按“相对参照的偏离”调整，接口预留不等于效果已估计。

5. 有什么验证证据

• 新能源年度参照链一年期WAPE：国内约7.07%、出口约36.21%、总量约1.32%。总量小误差有高估与低估抵消，不能据此说两条业务分支都可靠；实际年份也很少。

• ABS训练内选模规则的未来12个月规模合计WAPE约11.57%，最近月基线约21.08%；同一选模规则的月度WAPE约21.61%，合计会掩盖月度偏差。

• 匹配2027提前程度的第4—15月规模合计WAPE约14.09%；匹配2028的第16—27月约23.65%，后者只有7个重叠起点，不是7年独立验证。

• 已通过37项行为检查、Skill格式检查、云端运行检查；从GitHub下载后两个行业能重跑，预测CSV与交付结果一致。这些证明程序和记录可复现，不证明因果参数有效或真实企业业务已验收。

一个经营演示：仅在教学假设“承接计划数份额2%、每只计划1200工时、可用36000工时”成立时，ABS基准1657只对应39768工时，缺口3768工时。可据此讨论弹性人力或分批承接，不能当作某家公司的真实缺口。

6. 汇报时必须保留的不足

新能源汽车年度参照仅五年，月度57个月中4个月为累计差分，有12项年／月汇总差异尚待解释。外部弹性有样本迁移问题，完整宏观／成本／政策情景链尚未历史验证。

ABS虽有81个月，但缺首次发布版本、可比融资成本、资产池、发行失败／延期、评级期限及投资者资料。利差、宏观和政策的数量影响尚未实证估计；悲观、乐观幅度是规划压力条件。不能对外说“所有经济变量已经进入回归”。

两行业都缺真实企业订单／管线、份额、成本及风险容忍度；教学参数不是企业事实。三情景不是统计置信区间，数千条网格不是数千个历史样本，也不能承诺预测准确率。

7. 后续组员怎样接手

先解压完整包，打开“开始使用.html”；需要运行时双击 demand-forecast 文件夹里的“选择行业运行.cmd”。先保持输入不变跑通，再改一个情景并保存到新输出目录。

数据、参数和模型修改入口见维护交接。不要直接修改结果CSV来让它看起来更好；先改输入或模型，再重跑并检查分支、提前期及业务条件。更新信息日期时还需重新核验数据、政策和校验规则。

GitHub仓库目前为私有。没有仓库访问权限的组员可以直接接收完整ZIP运行；本文和讲稿只提供说明，不能代替运行所需数据与程序。后续优先补同口径历史和企业实际输入，再考虑复杂模型或扩展其他行业。
